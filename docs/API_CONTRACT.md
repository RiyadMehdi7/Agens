# API contract — integration skeleton

Runtime schemas live in `shared/data.ts` and `shared/api.ts`. The original `Dataset`, `QueryResult` and `DataAdapter` interfaces remain compatible; `normalizedRequest` adds immutable rich query provenance. This branch supplies transport and an injectable service. It does not implement parsers, databases, Gemini voice or chart planning.

## Transport and sessions

API listens only on `127.0.0.1`, default port5190. `APP_ORIGIN` sets the exact browser-facing HTTP(S) origin; default is the API's loopback origin. Vite must preserve browser Host and Origin through its same-origin `/api` proxy. For example, `APP_ORIGIN=http://127.0.0.1:5173 npm run dev`; with a forwarded frontend port15173 use `APP_ORIGIN=http://127.0.0.1:15173`. No origin wildcards, Host-derived allow lists, or public exposure.

The first non-health request without a cookie receives an opaque server-generated `agens_session` cookie (`Path=/api; HttpOnly; SameSite=Strict`, `Secure` for HTTPS). A supplied invalid/expired cookie gets401 and is cleared; the client may deliberately retry without the stale cookie. Session IDs are not accepted in URL/body. Ownership is enforced on every dataset/query lookup. Foreign IDs return404; mismatched owned dataset/query references return409. These are development browser sessions, not account authentication or durable storage. A production deployment needs its own authenticated ingress and storage lifecycle.

POST bodies use uncompressed `application/json`, optionally `charset=utf-8`. Bodies are capped512KiB, imports256KiB decoded (base64 field<=350000chars). Header/body reads and connections are bounded. Responses are JSON, no-store, nosniff. Error envelope:

```json
{"error":{"code":"NOT_IMPLEMENTED","message":"This capability is not implemented."}}
```

Codes: INVALID_REQUEST400, PAYLOAD_TOO_LARGE413, UNSUPPORTED_MEDIA_TYPE415, UNAUTHORIZED401, FORBIDDEN403, NOT_FOUND404, CONFLICT409, RESOURCE_LIMIT429, NOT_IMPLEMENTED/UNAVAILABLE503, INTERNAL_ERROR500. Stack traces, credentials and provider details are not returned. Validation rejects unknown fields.

## Routes

| Method/path | Request | Response |
| --- | --- | --- |
| GET `/api/health` | none | status/stage/availability; no credentials |
| GET `/api/datasets` | none | `{datasets: Dataset[]}` or503 without adapter |
| POST `/api/datasets/import` | ImportRequest |201 `{dataset: Dataset}` |
| POST `/api/query` | QueryRequest | `{result: QueryResult}` |
| GET `/api/queries/:queryId` | none | stored immutable `{result: QueryResult}` |
| POST `/api/live/token` | `{requestId?: string}` |503 until issue#4 |
| POST `/api/dashboard/plan` | PlanRequest | validates evidence ownership then503 until issue#4 |
| POST `/api/tools/execute` | `{name,arguments}` | same data/plan result or typed error |

Default health reports stage `integration-skeleton`, all capability availability `unavailable`, voiceImplemented=false and dataConnectorsImplemented=false. Injecting an adapter changes availability.data to `adapter-injected` while leaving implementation flags false: an injected fixture is not proof of connected data.

ImportRequest (CSV example):

```json
{"format":"csv","name":"Revenue","contentBase64":"YW1vdW50CjEwCjIwCg==","requestId":"import_1"}
```

`format` csv/xlsx; `name`1..200chars; optional xlsx `sheet`1..100chars; optional requestId bounded identifier. Sheet selection is supplied by name; this contract does not yet expose workbook sheet discovery. Parser behavior is owned by issue#2. Import returns one validated Dataset. Public source/dataset IDs are generated by this service and mapped to private adapter IDs.

QueryRequest example:

```json
{"datasetId":"owned_dataset","requestId":"query_1","filters":[{"field":"amount","op":"gte","value":{"type":"number","value":10}}],"aggregates":[{"op":"sum","field":"amount","alias":"total"}],"sort":[{"field":"total","direction":"desc"}],"limit":100}
```

Dataset schema exposes columns with string/number/boolean/date types, rowCount, UTC capturedAt and freshness snapshot/live/sample. IDs match `[A-Za-z0-9_-]{1,80}`. Fields max100chars; prototype-related names rejected. At most100 unique columns,32 filters,100 IN values,20 aggregates,20 sort fields and1000 result rows. Scalar strings max4096chars. Numbers finite, never coerced from text. Date literals are valid UTC ISO timestamps with milliseconds.

Queries may use projection or aggregates, not both. groupBy requires aggregates. Aggregation aliases are unique identifiers and cannot collide with groupBy. Sort fields must belong to output; unknown dataset fields and incompatible literal/aggregate types are rejected before execution. `filters`, `sort`, and `limit` default to `[]`, `[]`,100. requestId is correlation metadata, not an idempotency promise. No SQL, JS or model-generated expressions.

### Deterministic adapter semantics

The issue#2 engine must follow this specification; the API validates input/output and provenance but does not execute the query:

- All filters combine with AND. eq/ne use typed exact equality; null is equal only to null. IN uses those same comparisons. Ordered comparisons exclude null; numeric values compare numerically, UTC dates chronologically, strings by code point with no locale coercion.
- Grouping uses exact typed values, with null as its own group. `count` without field counts rows; with field counts non-null values. sum/avg/min/max ignore null; empty sum/avg/min/max return null. Ungrouped empty input yields a single aggregate row (count0); grouped empty input yields no rows. Non-finite numeric results are errors.
- Sorting is stable and applied before limit, with null last in both directions. Ties preserve source/group encounter order. Projection retains requested column order. `truncated` is true when a limit omits matching output rows.
- Every output row has exactly the requested output fields. Numeric/boolean/date values match declared types; null is allowed. Evidence capture time, original filters and an aggregation description must be accurate. The service replaces adapter IDs and normalizedRequest with validated public references and deep-copies stored evidence.

QueryResult example:

```json
{"queryId":"owned_query","datasetId":"owned_dataset","rows":[{"total":30}],"capturedAt":"2026-10-03T00:00:00.000Z","filters":{},"aggregation":"sum(amount)","truncated":false,"normalizedRequest":{"datasetId":"owned_dataset","filters":[],"sort":[],"aggregates":[{"op":"sum","field":"amount","alias":"total"}],"limit":100}}
```

The legacy `filters` object remains usable. Rich normalizedRequest records all operators/typed values; consumers should use it for full filter evidence.

PlanRequest: optional requestId, prompt1..4000chars, current shared Dashboard, evidence array<=50 `{datasetId,queryId}` references. Every explicit reference and dashboard chart reference must resolve within the session. Token/provider response schemas land in#4, not invented here.

Tool names: `list_datasets` with empty arguments; `query_data` with QueryRequest; `get_query` with datasetId/queryId; `plan_dashboard` with PlanRequest. No arbitrary tool names or raw code.

## Adapter injection handoff

`createApiServer({origin,createAdapter})` takes a factory producing a fresh `SessionDataAdapter` for each session. Import receives `(ImportRequest,{signal})`; query receives `(internalDatasetId,validatedRequest,{signal})`. Factory receives sessionId and lifetime AbortSignal; optional dispose runs on expiry/close. Do not share mutable adapter state across sessions. The original DataAdapter contract remains a base interface; the HTTP extension is in `server/http/service.ts`.

Default limits:32 sessions,30min fixed lifetime,20 datasets and50 queries per session,2MiB retained metadata/evidence,one in-flight data operation per session,5sec operation deadline. On timeout the service aborts the signal; an adapter ignoring abort keeps its busy slot until it settles. Adapters must bound imported raw storage themselves and dispose it; the evidence budget does not bound a misbehaving adapter's private memory. No server/data files are owned or changed here.
